# TraderX v1.0 autonomous research acceptance

Verified October 17, 2026. This completes the bounded v1 research implementation and freezes its feature scope. Source remains local and unpublished: no commit, push, tag or release was made. The prior [v1 cleanup report](V1_FINAL_REPORT.md) remains the baseline; the results below supersede its test counts. This is working research/paper software, not evidence of profitable autonomous trading.

## Architecture and supported scope

Observations → constrained Director → immutable preregistration → isolated historical experiment → reject/challenger → existing scientific forward study → qualification evidence → explicit reviewed model registration.

The Director observes saved alpha health/dependence, qualification gate counts, coverage, completed forward IDs, rejected hypotheses and timestamped news categories. Four interpretable deterministic templates cover momentum/regime, reversion/liquidity, adverse news/momentum and cross-sectional momentum. Changed observations and prior hypotheses constrain selection; the system does not enumerate arbitrary combinations. The optional local/cloud Director receives narrative questions and failure/event categories, not market ticks or accounting/risk calculations. Global AI-off and existing provider budgets still apply. No chatbot was restored.

The `autonomous-v1` schema freezes an economic hypothesis, eligible universe, asset class, whitelisted features/transforms, Ridge/logistic model, target/horizon, regime, long/cash portfolio, benchmarks, costs, liquidity assumptions, training window, bounded trials, chronological validation and predefined success criteria. Extra fields, arbitrary code, unsafe paths and unsupported models fail validation before execution. Existing advanced model research remains available separately; automatic neural architecture search is not implemented.

Preregistration stores immutable source IDs/archive references, checksums, implementation/dependency hash, holdout boundary, model/search bounds, costs, metrics, criteria, time, novelty, lineage and attempt allocation. A changed dataset or interpreter rejects the run. Training matrices are reconstructed into disposable files, not archived again.

## Governance and isolation

All attempts, including failures, consume a permanent index. The frozen threshold allocates alpha over attempt index, trial count and two benchmarks. Descriptive Benjamini–Yekutieli adjustment includes failed/missing p-values as 1. Related feature families/lookbacks inherit lineage; high feature/universe/target/model/economic overlap rejects redundant proposals. Shared-date prediction correlation provides an additional redundancy screen. Neither correction nor bootstrap inference establishes guaranteed false-discovery control for adaptively reused historical data.

Defaults: paused; optional Director off; one experiment/day, one worker, 30 CPU seconds, 60 wall seconds, 768 MB monitored RAM, two trials, six hours between evidence reviews, 64 MB logical research payload/file budget and 500 permanent registrations. CPU, memory, time, daily execution, storage, trial and concurrency limits fail closed. Permanent evidence is retained at capacity; new work stops. Shared database/WAL overhead is excluded from this module's displayed storage quota.

The fixed trusted worker gets plain JSON and a clean environment without broker/API credentials. It has no broker/order/transfer tools. Network/subprocess/protected-file operations are denied, output is bounded, and temporary directories are removed after success, rejection or interruption. Python audit hooks protect a trusted interpreter; they are not represented as a secure sandbox for hostile native code.

Generated implementation proposals are text under ignored `research/proposals/auto-…/`, with rationale, patch text, tests, data and experiment design. Approve/reject records a human review decision only. No action applies or executes a proposed patch.

Historical success creates a CHALLENGER only. Explicit enrollment reuses scientific forward execution with frozen cost/size policy, feature provenance and untouched evaluation evidence. No autonomous production promotion endpoint exists. Prospective benchmark qualification and reviewed versioned model/ensemble registration remain mandatory. No qualified autonomous discovery is claimed.

Because the forward adapter changes the frozen implementation hash, 27 existing qualification definitions and three comparison portfolios were registered for the current implementation; old definitions/results remain intact. All 27 are FORWARD_TESTING. Twelve alpha families were registered against current versioned provenance. This starts fresh evidence windows where required and does not promote models or reuse old observations as new proof.

## Run and remaining limitations

Open `TraderX.command` in the desktop project and keep its window open, then visit http://localhost:3000. Use Research → Autonomous Research → Resume only when you want bounded template experiments. No API key is required for that research path. Optional local/cloud hypothesis generation requires the configured provider; paid chat subscriptions do not substitute for API billing. [START_HERE](../START_HERE.md) lists the actual provider configuration.

This phase does not train a financial language model, restore chat, expand automatic models beyond Ridge/logistic, invent missing historical news or supply future independent observations. Historical opens plus adverse costs are research scenarios, not reconstructed fills. Finite bootstrap resolution can make later significance thresholds unreachable; the system rejects rather than relaxing them. Sparse features, current-universe bias and dependence remain documented limitations. Qualification and eventual production eligibility require real elapsed evidence and explicit reviewed registration; no amount of API configuration automatically proves alpha.
